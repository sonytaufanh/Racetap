# Racetap

Race timing and event technology platform. A CodeIgniter 3 backend serves the
JSON API and three React single-page bundles: the public site + admin, the
per-event results viewer, and the BIB-check / result kiosks.

## Features

**Public site** — Home, About, Services, Clients & testimonials, FAQ,
Contact (lead intake), Privacy/Terms, event detail pages with podium and
participant stats, global search (events + athletes across events), an
**Indonesian/English switch** (persisted, updates `<html lang>`, also available
inside the results viewer), dark mode, and a results grid. The navbar carries the
primary navigation (Home, About, Services, Results, Photos, Contact)
plus language, search, theme and WhatsApp actions; the footer repeats them with
the secondary pages. Page headers are compact (breadcrumb + title + subtitle +
actions) and every listing page (Results, Photos, FAQ) has a search/sort toolbar.
The home hero includes a quick **result search** that queries athletes across
events and deep-links to the results viewer with the bib highlighted.

**Results viewer** (`/results/<slug>/`) — podium per distance, searchable/sortable table,
filters, statistics charts (gender, age group, finish time), athlete modal with
splits and rankings, favorites, CSV export, print layout, live auto-refresh,
share links, URL-state (every filter is linkable), and dark mode.

**E-certificates** — per-event certificate templates authored in the admin
(`/admin/sertifikat`): upload the artwork, then drag each field (name, BIB,
gender, distance, net/gun time, finish time, ranks, age group, city, team, event
name/date) onto the design with its own font, size, weight, italic, colour,
letter spacing, rotation, alignment and auto-shrink width. The layout is stored
as `results/<slug>/certificate.json` next to `certificate.<ext>`, so the static
viewer renders it without an API call. Participants open it from the results
table and download a PNG or PDF; the page is drawn in the browser, so the file is
pixel-identical to the editor preview. Events without a template (or
non-finishers, when "only finishers" is on) keep the timing-provider link.

**Kiosks** (`bibcheck*.racetap.id`, `result*.racetap.id`) — config-driven BIB
check / result displays with fullscreen, wake lock, idle reset, category
backgrounds and gender mapping.

**Admin** (`/admin`) — dashboard KPIs and activity, race management with sync
preview, photo library (drag-drop upload, search/filter, bulk BIB/OCR/delete,
lightbox), certificate designer, OCR queue, contact inbox, site settings, audit
log, and user management with roles (superadmin/admin/operator).

## Layout

```
application/            CodeIgniter 3 app (controllers, models, config, views)
  controllers/api/      JSON API v1 (public + admin)
  controllers/Spa.php   HTML shells + per-page meta/JSON-LD
  views/spa/index.php   Site shell rendered by Spa::index
assets/app/             Build output (gitignored, regenerate with `npm run build`)
assets/images/          Site imagery and photo galleries
web/                    React + TypeScript sources (Vite)
  src/                  site + admin SPA
  src/results/          per-event results viewer + events.json manifest
  src/certificate/      certificate renderer, tokens/fonts catalog, admin editor UI
  src/assets/fonts/     self-hosted woff2 catalog (generated by scripts/vendor-fonts.mjs)
  src/kiosk/            BIB-check kiosk + instances.json manifest
  scripts/              shell generators, sitemap + font vendoring
results/<slug>/         static per-event results pages (index.html + data.json)
                        + optional certificate.json / certificate.<ext>
bibcheck*.racetap.id/   kiosk vhosts (check stations)
result*.racetap.id/     kiosk vhosts (result stations)
local*.racetap.id/      offline variants of the kiosks (dataSource: local)
system/                 CodeIgniter 3 framework
database/schema.sql     schema (new tables: app_settings, leads, audit_log)
router.php              router for PHP's built-in server
```

Every directory under `results/` and every `*.racetap.id/` kiosk directory is a
real docroot on the shared host, so pages are plain `index.html` shells that load
the shared bundles from `assets/app/`.

## Local development

From the repository root:

```bash
npm run dev            # starts PHP (127.0.0.1:8180) + Vite (127.0.0.1:5173)
```

`npm run dev` launches the PHP backend (unless port 8180 is already in use) and
stops it when Vite exits. Use `npm run dev:web` for Vite only, or `npm run
dev:php` to run the backend manually.

`router.php` emulates the production `.htaccess`: real files are served
directly, dotted kiosk directories fall back to their `index.html`, and
everything else goes through CodeIgniter.

In dev, `/assets` (images, photos, covers), `/favicon.ico`, `/apple-touch-icon.png`,
`/sitemap.xml` and `/robots.txt` are served straight from disk, so the UI keeps
rendering even when PHP is stopped. Only `/index.php/*` needs the backend; when
it is down the dev server answers a JSON `503` instead of spamming proxy errors.
Point the API elsewhere with `RACETAP_PHP_URL` (default
`http://127.0.0.1:8180`); keep the local `APP_BASE_URL` in
`application/config/.env` on the same origin.

Dev entry points:

| URL | Serves |
|---|---|
| `http://127.0.0.1:5173/` | public site + `/admin` |
| `http://127.0.0.1:5173/results` | results grid |
| `http://127.0.0.1:5173/results/jember-10k/` | single event results viewer |
| `http://127.0.0.1:5173/events/jember-10k` | event detail page |
| `http://127.0.0.1:5173/bibchecklocal.racetap.id/` | kiosk station |

To test a kiosk from another device on the LAN: `npm run dev -- --host`.

Production-like run (uses the built bundles in `assets/app/`):

```bash
npm run build
npm run dev:php
```

## CLI tools

```bash
php index.php tools migrate        # idempotent schema upgrade + superadmin promotion
php index.php tools index_results  # import results/*/data.json into race_results (search index)
php index.php tools seed_photos    # seed the photo library from assets/data/photos.json
php index.php tools check_media    # report photo rows/covers whose files are missing on disk
php index.php tools certificates   # per-event certificate state (template + field count)
php index.php tools certificates jember-10k   # dump one event's stored layout
php index.php cron_race_sync sync_due_events
```

Media filenames are normalized to be URL-safe (spaces become dashes) and asset
URLs are URI-encoded, so covers such as `ahy-run-2026.webp` load on every
server. Use the admin dashboard's **Periksa media** button (or
`tools check_media`) after a deploy to confirm every photo file was uploaded.

Run `migrate` once after deploying: it creates `app_settings`, `leads`,
`audit_log`, adds `admin_users.role` and `photo_events.ocr_rule` (per-event OCR
rule), and promotes the first admin to superadmin. Run `index_results` whenever
new results are published — it powers the public cross-event athlete search.

## Photo library flow

1. Admin uploads photos in **Admin > Photos > Galeri**.
2. OCR runs automatically when the admin presses **Index OCR** (progress bar with
   percentage, current file, and a cancel button). The engine is picked
   automatically: **RapidOCR** (free, self-hosted, see `ocr_service/`) first,
   then **PaddleOCR** (free, self-hosted, see `ocr_service_paddle/`), Azure
   Vision F0, OCR.space, Google Vision (premium, when `GOOGLE_VISION_API_KEY`
   is set) and finally browser Tesseract. A fallback only happens when an
   engine errors; there is no engine dropdown in the UI.
3. One photo can contain several runners, so every detected bib is stored in
   `photo_bibs`. Candidates are validated against the event's `race_results`
   whitelist, which removes times, years and distance numbers. Manual correction
   lives in the photo lightbox.
4. Only photos that finished OCR (ocr_indexed_at set) appear on
   `/photos/<slug>` - even when no bib was detected.

### OCR rules per event

Every photo event carries its own OCR rule, set in **Admin > Photos > Edit
event > Aturan OCR**:

- **Jumlah angka pada nomor BIB** — pick the exact digit count (4, 5, 6, ...).
  Digit runs of any other length are ignored, so a 5-digit year never lands in
  `photo_bibs`. "Belum ditentukan" keeps the legacy 3-6 range.
- **Hanya angka (0-9)** — the browser Tesseract whitelist drops every letter, and
  the server resolver ignores alphanumeric candidates.

Letters that look like digits are still repaired first (`O`→0, `I`/`L`→1,
`S`→5, `B`→8, `Z`→2, `G`→6, `T`→7), so an OCR read of `1O42` resolves to `1042`.
When the event has an official bib list (`race_results`), a glued read is also
repaired against it: RapidOCR reading `14127` resolves to bib `1412` — and only
for bibs that really exist in the event.

Rules apply to photos scanned **after** saving; press **Scan ulang** in the
gallery to re-index existing photos with the new rule.

### RapidOCR is required

RapidOCR (self-hosted, free) is the primary engine and is always tried first.
`application/config/ocr.php` sets `ocr_required_engine` (env
`OCR_REQUIRED_ENGINE=rapidocr`, the default), which makes it the **only** engine:
a stopped service raises an actionable error in the admin instead of silently
re-indexing photos with a weaker engine.

```powershell
# Windows: creates the venv on first run and serves on 127.0.0.1:8010
powershell -ExecutionPolicy Bypass -File ocr_service\start.ps1
```

```bash
# manual
cd ocr_service && .venv/Scripts/python -m uvicorn app:app --host 127.0.0.1 --port 8010
```

Set `OCR_SERVICE_URL` in `application/config/.env` if the service runs elsewhere
(or on another host/port). To allow a fallback to the next healthy engine during
development, set `OCR_REQUIRED_ENGINE=` (empty) — RapidOCR is still tried first.
The gallery shows a red banner with the exact command while RapidOCR is down.
5. Visitors can search by any indexed bib, select photos and download them
   individually or as a ZIP
   (`GET /api/v1/photos/events/<slug>/download?ids=1,2,3`).

### OCR engines

Copy `application/config/.env.example` to `application/config/.env` and fill the
keys you want to use. Empty engines are skipped.

| Engine | Cost | Setup |
|---|---|---|
| RapidOCR (recommended free) | Free, unlimited | `ocr_service/` microservice + `OCR_SERVICE_URL` |
| PaddleOCR (free) | Free, unlimited | `ocr_service_paddle/` microservice + `PADDLEOCR_SERVICE_URL` |
| Azure AI Vision F0 | 5.000 transactions/month free | `AZURE_VISION_KEY`, `AZURE_VISION_ENDPOINT` |
| OCR.space | Free key (~1 MB per image) | `OCRSPACE_API_KEY` |
| Google Vision | 1.000 units/month free, then paid | `GOOGLE_VISION_API_KEY` |
| Tesseract.js | Free | No setup (runs in the admin browser) |

`OCR_ENGINE_ORDER` controls the automatic order (default
`rapidocr,paddleocr,azure,ocrspace,vision,tesseract`). Both local engines are
optional: an unreachable microservice is skipped and the chain moves on.

PaddleOCR runs on its own port (`8015`) and virtualenv because PaddlePaddle
pins different numpy/opencv versions than RapidOCR:

```bash
cd ocr_service_paddle
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8015
```

Windows shortcut: `powershell -ExecutionPolicy Bypass -File ocr_service_paddle\start.ps1`
(creates the venv on first run).

### Google Vision API key

1. Open `console.cloud.google.com`, create/select a project, enable **Cloud
   Vision API** and billing (the free tier still applies).
2. **APIs & Services > Credentials > Create credentials > API key**.
3. Restrict the key to Cloud Vision API (and the server IP when possible).
4. Add `GOOGLE_VISION_API_KEY=AIza...` to `application/config/.env` (or set it as
   a real environment variable). No rebuild is required.
5. Verify with `GET /api/v1/admin/photos/events`: `vision_enabled` becomes
   `true`.

After deploying the multi-bib feature run `php index.php tools migrate` once; it
creates `photo_bibs` and backfills the legacy single-bib column.

## Adding content

Results event:

1. `mkdir results/<slug>` and drop `data.json` (scores feed) plus a `banner.*`.
2. Add an entry to `web/src/results/events.json` (`slug`, `name`, `location`,
   `cover`, `banner`, `columns`, `filters`, …; `latest: true` for the home page).
3. Add `results/<slug>/sync_api.sh` (copy an existing one, change `API_URL`).
4. `npm run gen` — it also writes `results/<slug>/summary.json` (counts, categories,
   per-distance podiums) used by the event detail page, then verify `/events/<slug>`
   and `/results/<slug>/`.
5. `php index.php tools index_results` to include the event in search.

The manifest powers the public Results grid, the Home "Latest event" block, the
event detail page, the admin results link, the sitemap, and the static shells —
see `web/src/lib/events.ts`.

Event certificate:

1. Open **Admin > Sertifikat**, pick the event, upload the artwork
   (JPG/PNG/WebP, max 8 MB, min 400x400).
2. Press **Tata letak contoh** for a starting layout, then drag each field onto
   the design and adjust font, size, colour and alignment. `Ctrl/Cmd + S` saves.
3. Turn on **Aktifkan sertifikat** (and optionally **Hanya peserta finisher**).

This writes `results/<slug>/certificate.json` + `results/<slug>/certificate.<ext>`
only. No rebuild and no `npm run gen` are needed: the viewer fetches
`certificate.json` next to `data.json` at runtime. Field coordinates are stored in
template pixels, so re-uploading a larger version of the same artwork only
requires re-placing the fields once.

Kiosk station:

1. Copy a kiosk directory (e.g. `bibcheck2.racetap.id`) and adjust
   `setting-*.json` (`apiUrl`, background, category mapping, field positions).
2. Add it to `web/src/kiosk/instances.json`.
3. `npm run gen` to write its `index.html`.

## Server configuration

- `application/config/.env` (not in git): `APP_BASE_URL`, `DB_HOSTNAME`,
  `DB_USERNAME`, `DB_PASSWORD`, `DB_DATABASE`, `GOOGLE_VISION_API_KEY`.
- Root `.htaccess` is the CodeIgniter front controller.
- `results/<slug>/sync_api.sh` pulls the external scores feed into `data.json`;
  run it from cron (example every 5 minutes):
  `*/5 * * * * /path/to/results/<slug>/sync_api.sh >/dev/null 2>&1`
- `sitemap.xml` and `robots.txt` are generated at the repo root by `npm run gen`
  (override the base with `node scripts/gen-sitemap.mjs --base=https://…`).

## API

Public:

| Endpoint | Purpose |
|---|---|
| `GET /api/v1/health` | Health probe (DB, results dirs, sitemap, build) |
| `GET /api/v1/settings` | Public site settings (contact, socials) |
| `GET /api/v1/photos/events` | Photo albums + stats |
| `GET /api/v1/photos/events/<slug>?bib=` | Album photos, optional BIB filter |
| `GET /api/v1/search?q=` | Cross-event athlete search (name/BIB) |
| `POST /api/v1/leads` | Contact form intake (rate limited + honeypot) |

Auth: `GET /api/v1/auth/session`, `POST /api/v1/auth/login|logout|setup`.

Admin (session + `X-CSRF-TOKEN`): `GET /api/v1/admin/stats`,
`/admin/settings`, `/admin/audit`, `/admin/users` (+`/users/create`,
`/users/<id>`), `/admin/leads` (+`/leads/<id>`), `/admin/races` (+`/sync`,
`/toggle`, `/results`), `/admin/photos/*`, `/admin/certificates`
(+`/<slug>` read/save/delete, `/<slug>/template` upload, `/<slug>/sample`).

Per-event results are static files under `/results/<slug>/`; the legacy
`/hasil` and `/race/<slug>` links redirect to the Results grid. Certificates read
`results/<slug>/certificate.json` directly (no API call), and the upload template
landed at `results/<slug>/certificate.<ext>`.
